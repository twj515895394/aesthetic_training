## Spec-as-Learning 工作方式

- 一次只 Grill 一个设计决策；每个问题附推荐方案及理由。
- 用户明确确认后，先在 `07-decision-log.md` 更新状态和原因，再把确定的规则同步到专题文档。
- 尚未确认的细节必须写作「建议（未确认）」或「待决」，不得以“规范”名义强制执行。
- 训练素材、实践结果和知识卡在后续逐步建立；不要用空洞的占位素材充数。
- 每个知识点记录案例、个人观察、可复现的操作、适用边界；允许修正旧结论。

## 状态定义

- **已确认**：用户本轮明确同意，或此前作为确认过的规则持续使用。
- **建议（未确认）**：教练建议，但还没有逐项 Grill 决策。
- **待讨论**：有依赖关系、需后续决策的问题。
- **实验结论**：训练中的个人观察，不能冒充普适定律。

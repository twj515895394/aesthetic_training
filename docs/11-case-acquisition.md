# 11｜案例获取、来源核验与持续积累

> 状态：**D-015 按课积累、D-016 本地媒体、D-020 经典标杆 + 当代优秀作品 + 必要反例**均已确认。候选库具体数量和由谁完成最终选材检查待讨论。本文不表示已经收集或验证了真实作品。

## 1. 核心目标

在跨领域视觉训练中建立一个可持续、可追溯、可复用的案例资料库，支撑每天的**1 个主案例 + 1 个不同领域对照案例**。案例库不是影视截图集，也不是无标签的图片下载目录。它应能回答：

- 哪个作品适合研究「视觉焦点、留白、光影、色彩」等概念？
- 为什么选这个作品？同一概念在另一媒介里如何表达？
- 原作/作者与可靠出处是什么？公开仓库是否能合法保存图片？
- 这件作品被用于哪些日常训练、实验、知识卡与复盘？

## 2. 已确认的策略：小型基础候选库 + 按课即时补充

### 2.1 先有少量候选，不预先堆大库

- 按 12 周主题的近期需要以及领域维度（摄影、绘画、电影画面、平面设计、广告、空间等）准备一批**小型、可信的候选**。
- 未正式使用的候选可以先只有作品名、来源链接、领域和可研究的知识点；不必提前对几十/几百张图片逐一写长分析。
- 基础库具体需要几张、每个领域占多少比例，尚待根据训练数据观察，不视为已批准的固定数量。

### 2.2 每天按目标选取 1+1

1. 根据当前 Wxx-Dxx 的**主知识点、实验等级、已发现的薄弱项**写出当天视觉研究问题。
2. 从候选里选择一个最能展示该问题的主案例。
3. 找到**不同视觉领域**且可在相同知识点上比较的对照案例；优先有可核验作者/来源的作品。
4. 如果候选不足、学员提供新个人作品、或自适应复习需要特殊画面，则当日按需增补。
5. 确保案例有辨认价值；不要为了凑满两张而降低质量。复盘日可例外，不强制两张新作品。

### 2.3 真正使用后才做完整案例卡

- 实际用于分析/实验的作品应建案例资料卡，关联 `main_case_id` / `compare_case_id`、视觉知识点和训练记录。
- 同一作品反复用于不同周次时**复用同一案例卡**、追加 `related_sessions`，不要复制出多个互不关联的文件。
- 若只是候选、尚未观察或未用于训练，不要把 AI 想象出来的分析填成“学员已学会”。
- 个人案例随时纳入：自己拍摄、创作的作品与个人收藏的第三方作品都可以作为**学习对象**，但其文件能否公开发布要分别核验。

## 3. 高质量案例的选材原则（D-020 已确认）

**来源构成**：结合经典标杆、当代优秀视觉作品与必要反例。经典作品帮助建立基准，当代作品促进实际应用；反例用于讨论视觉手法的适用边界，不能简单等同于“丑图”。这里不设置机械配比，也不按热门程度、名气或数量代替教学价值。

**维持 1+1 课时负担**：普通日仍是一张主案例与一张跨领域对照。需要反例时，可让其中一张承担反例角色、采用同图裁切/变体比较，或在之后的课次中分析，不要求每天新增第三张完整案例。

**轻量选材检查**：

- **相关性**：能否突出本次研究的一个视觉现象，而不只是“热门”或“好看”。
- **可观察性**：图像是否足够清晰，能看出所讨论的结构，且适合学员先独立观察。
- **可比性**：主案例与对照案例是否有共同视觉问题，又有媒介差异。
- **多样性**：不同媒介、风格、地区和年代是否都得到合理覆盖，避免只有电影感/人像摄影。
- **可溯源性**：是否可以找到作者、作品名、原始或可信的收藏机构、发布机构和具体链接。
- **合法性**：图片能否作为公开仓库中的文件另行判断；公开网页可浏览不等于可公开再分发。

若作者/来源不确定，就在卡片里注明「待核实」，不能硬填看似合理的信息。

## 4. 来源与许可状态

| 来源类型 | 首选处理 | 注意 |
|---|---|---|
| 博物馆、艺术馆、摄影师/设计师官方作品页 | 保存作品名、作者、源网页链接、馆藏或来源信息及许可声明 | 每件图像可能有不同的许可，需看具体作品页 |
| 影视剧照与商业广告 | 保存出处链接、影片/广告名称、研究用途、原创分析 | 不因能截图或检索到就默认可作为公开媒体文件入库 |
| 学员自己创作的照片、插画或 AI 辅助作品 | 保存来源、创作背景、可公开性与关联实践 | 公开仓库不上传敏感个人内容；留意素材组成部分的权限 |
| 从社交媒体收藏的第三方作品 | 保存原发布链接、已知作者、观察理由，必要时标「授权未知」 | 转载账号未必是作者；不要未经核验复制到公开仓库 |

**无明确合法再分发依据**：只在公开项目中保留原作链接、来源信息和自己原创的分析笔记，不提交原始图片，也不把公开仓库当作第三方作品镜像站。

许可相关建议枚举见 [05 素材管理规范](05-asset-management.md)。**Q-006 已确认本地优先**，素材默认留在被 Git 忽略的 `local-assets/`，GitHub 只保存公开元数据与可分享的原始来源链接；具体见 [12 本地媒体管理](12-local-asset-storage.md)。

## 5. 最小流程与文件关联

```text
周主题/当日目标
  ↓
少量经典与个人候选（候选记录）
  ↓
挑选一张主案例 + 不同领域对照案例
  ↓
核对作者/作品/可信来源/许可
  ↓
开展观察、跨领域比较及对应等级的实践
  ↓
创建或更新 materials/{classic|personal}/作品资料卡
  ↓
将 case ID 关联 practices/daily/Wxx-Dxx-*.md
  ↓
复盘时把有效观察归纳到 knowledge/ 概念卡
  ↓
下一周继续从已有候选与真实新需求中补充
```

推荐使用 [案例卡模板](templates/case-note.md) 作为已使用案例的详细结构；存储及文件命名参见 [05 素材管理规范](05-asset-management.md)。

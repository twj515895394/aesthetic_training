## Q-001｜每日反馈与纠错机制（已解决）

**结论：C 分级反馈，已确认（D-011）。** 初学知识点进行适量示范、即时纠偏；熟悉后优先让学员自主解释证据；教练提供针对性反馈，区分画面事实、可辩论的解释与改进建议。是否评分、精确反馈字段、追问轮次上限仍待后续细化。

## Q-002｜每日训练记录的最小字段与填写负担（已解决）

**结论：C 双层记录 + AI 辅助整理，已确认（D-012）。** 学员先独立表达观察、自评及依据；AI 整理真实对话、案例出处和实际实验为 Markdown 草稿；学员审核后才进入 GitHub。不得把 AI 推断包装成学员原话，也不得补造缺席的训练事实。具体元数据字段、命名与自动化触发细节可日后依据实操微调。

## Q-003｜学习成果评价与阶段进阶机制（已解决）

**结论：C 证据驱动的混合评估，已确认（D-013）。** 每日保存真实观察与实验；每周独立分析陌生作品并完成一次知识迁移；W04/W08/W12 把早期与近期证据并排分析。观察证据、解释能力、表达意图、改造结果和跨领域迁移是关注维度；仅在有必要时用轻量等级辅助跟踪，不以主观风格偏好给出“审美分”。细节见 [09 评估与复盘机制](09-assessment-and-review.md)。

## Q-004｜难度自适应与薄弱项复习（已解决）

**结论：C 固定主线 + 薄弱项补练 + 逐步加难，已确认（D-014）。** 继续推进 12 周主题和 4+2+1 周节奏；根据真实训练记录，在当前主案例、对照或练习内嵌入先前薄弱知识点，不另增训练时长；掌握后逐步减少提示、引入陌生案例及跨领域迁移/创作。细节见 [10 自适应训练规范](10-adaptive-training.md)。触发阈值、复习占比与难度等级仍属待定参数。

## Q-005｜案例获取、来源核验与入库流程（已解决）

**结论：C 小型基础案例库 + 按课即时补充，已确认（D-015）。** 按周主题和领域准备少量有可靠来源的候选案例；训练中选 1 张主案例与 1 张不同领域对照；实际使用后再保存案例卡，记录作者/作品/原始出处/研究用途/授权状态。个人图片随时进入候选；无公开再分发许可的第三方作品只存来源链接及自写分析。候选库规模、质量评分、详细字段仍是实施细节，不预设未经确认的数量。详见 [11 案例获取与积累](11-case-acquisition.md)。

## Q-006｜案例图片与实战素材如何存储（已解决）

**结论：D-016 本地优先，已确认。** 用户会把仓库 clone 到本地；大部分素材在本地管理，不考虑同步大文件到 GitHub。GitHub 以 Spec、案例卡、知识卡、训练记录等 Markdown 为核心；建议本地二进制媒体统一放 `local-assets/`，由 `.gitignore` 默认排除。资料卡可记录可信原始来源 URL 和仓库相对的 `local_media` 路径，便于本地定位；远程网页不展示本机文件属于预期行为。无需先引入 Git LFS、云端对象存储或远程资产系统。具体约定见 [12 本地媒体管理](12-local-asset-storage.md)。

## Q-007｜案例、知识与练习如何索引复用（下一轮）

**问题**：当经典/个人案例逐步增多，如何通过“视觉知识点、媒介、周次、来源、练习结果”等条件找到过去的好案例，并在本地定位原图、标注与改版文件？

**待确认候选**：

- **A 只按目录浏览**：靠 `materials/classic`、`personal` 和每周文件夹找资料；几乎零成本，但跨知识点复用困难。
- **B 建结构化数据库或专用资产管理应用**：支持复杂筛选和预览；功能丰富，但要建设和维护额外系统，不利于当前轻量训练目标。
- **C Markdown 元数据 + 双向链接 + 汇总索引（推荐）**：为每个案例、知识点和训练建立稳定 ID，利用 YAML 标签、媒介类别、来源、训练关联和相对本地媒体路径形成跨文件索引；先用仓库目录/全文搜索，后续素材规模增长再考虑脚本索引或资产管理 UI。

**推荐理由**：与现有 `.md` Spec、双层记录、本地媒体优先方案一致，可以立刻在 GitHub 或本地搜索，不需要引入数据库；需要时再提升自动化。索引字段、是否生成索引页、用什么脚本仍属 Q-007 的实施细节。

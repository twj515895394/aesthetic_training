# 14｜课程会话、暂停续接与学习进度管理

> **D-018 / Q-008 已确认（2026-11-11）**：使用 **C 进度驱动的课程会话**。以真实完成的 `Wxx-Dxx` 为准，支持主动开始、暂停、继续、补课、查看进度和每周复盘；缺课不按日历跳过。以下状态字段与指令格式为**首版建议实现**，可在第一次真实训练后调整。

## 1. 核心约束（已确认）

- **课程序号不等于真实日期**：`W01-D01` 是课程单元标识，不是“必须在某年某月某日完成”的日历任务。真实训练日单独记录在 `date` 或训练事件中。
- **不自动跳课**：若停止三天，下次仍从最近未完成的同一单元继续。每周顺序保留四天精选、两天个人案例、一天复盘（D-006）。
- **真实完成才推进**：一节课需有实际观察/实战和复盘证据、AI 整理的记录、学员审核确认并归档，才能视为已完成（D-012）。
- **中断不丢事实**：已回答的问题、真实实验结果和剩余步骤可形成待审核的暂停快照；未完成部分不得填成已完成。
- **用户主动操作（D-019）**：开始、续接和查询进度均由学员发起；不创建自动提醒、定期推送或自动周报，也不假设具备后台监控或跨会话永久记忆。
- **本地 Agent 执行（D-023）**：先 clone 仓库，之后由本地 Agent 读取真实进度和素材并授课；当前 ChatGPT 规划过程不计入课程进度。
- **学习证据不虚构**：无 GitHub 或本地进度文件可读时，不能凭猜测断言进度。用户可提供记录或授权重新查阅。

## 2. 会话状态（首版建议）

| 状态 | 含义 | 是否计入完成进度 |
|---|---|---|
| `not_started` | 尚未开始任何真实训练 | 否 |
| `in_progress` | 正在学习或已中断，存在真实部分进展 | 否 |
| `pending_review` | 课程操作基本结束，AI 已整理记录，尚待学员审核/确认 | 否 |
| `completed` | 学员已确认记录且已成功归档，与训练索引一致 | **是** |

`in_progress` 不是“失败”或“缺课”；`pending_review` 不是 `completed`。若无法核实归档是否成功，保持待核验，不得擅自推进编号。

**首版存储入口**：[学习进度索引](../practices/progress.md) 与 [训练索引](../practices/index.md)。该文件可以在第一次训练时由 AI 依据实际证据起草更新，经学员审核后提交。已开始尚未完成的快照是否提交 GitHub，须尊重用户对 D-012 草稿审核的要求；未经审核不能自动同步。

## 3. 常用指令与预期行为（首版交互约定）

| 用户发起指令（自然语言可等价） | 预期行为 |
|---|---|
| **开始今日训练** | 先核对已审核的进度和未完成记录；若已有未完成单元，默认提示续接；否则进入下一个未完成 `Wxx-Dxx` |
| **继续上次训练** | 从最后一个**有证据**的暂停点恢复，不重复已经做过的内容；若找不到进度快照，应说明缺失 |
| **暂停训练** | 总结本次已完成事实、尚未完成项、下次起点；提供快照草稿，由用户确认后再归档 |
| **查看学习进度** | 列出最后审核完成的训练、当前进行中的课时、下一待做单元、待审核记录与已记录弱项 |
| **补课** | 返回未完成的单元继续，不因已过自然日期跳过；维持 12 周主线 |
| **本周复盘** | 只有当前周 D01–D06 已完成，才进入 D07 的正式周复盘；若未完成，可做非结业式即时回顾，但不得标记 D07 已通过 |

自然语言按钮/命令只是**交互协议**，不是已部署的自动化程序；AI 必须能读取实际文档或接收用户提供的进度记录，才能准确恢复跨对话会话。

## 4. 进度推进规则

```text
W01-D01 (not_started)
   ↓ 用户主动开始
W01-D01 (in_progress)
   ├─ 暂停 → 真实训练快照（待审核）→ 下一次续接
   ↓ 完成观察 + 对照 + 必要实践 + 复盘
W01-D01 (pending_review)
   ↓ 用户审核认可文档，并成功归档
W01-D01 (completed)
   ↓ 下一单元
W01-D02 ... W01-D06 (completed)
   ↓
W01-D07 每周复盘 (in_progress → pending_review → completed)
   ↓
W02-D01
```

- 同一单元的重复学习可作为额外练习记录，但不增加已完成课时计数。
- 日历日期用于记录何时学习，不能强制绑定到 D01=周一、D07=周日。
- 若上次课堂只完成了观察与主案例分析，下次从未完成的对照和实践继续。
- 周复盘采用 D-013 的陌生作品独立判断与跨领域迁移任务；不要因为日期到了周日就自动宣布完成。

## 5. 快照与归档（遵循 D-012）

建议暂停快照记录：

```yaml
---
session_id: W01-D01
status: in_progress
last_completed_step: observation
pending_steps: [comparison, theory, practice, reflection]
last_activity_date: YYYY-MM-DD
draft_record: "practices/daily/W01-D01-visual-focus.md"
---
```

快照还应以文字忠实概述学员的**原始观察**、当天确实看过的主/对照案例、已实际完成的练习，以及下次恢复时的第一个问题或操作。

这里列出的 ID、日期、路径是**格式演示**，并不代表上述 `W01-D01` 训练已经开始。字段名和步骤分类是当前建议，实现时以实际训练和已经通过审核的内容为准。

### 对话与 GitHub 之间的边界

- 在同一对话里可以根据当前对话继续；跨新对话，应读取 `practices/progress.md` 与对应练习记录（或由用户提供其内容），才能确认进度。
- 训练过程中 AI 可生成**待审核**的快照和 Markdown 草稿；由学员确认后再同步文本仓库。
- 本地 `local-assets/` 图片与视频不推送 GitHub（D-016），因此换设备或新对话若没有提供图片，不应声称已看过本机素材。
- **Q-009 已定案为 A 完全手动（D-019）**：无需配置自动提醒或周期报告。用户主动请求总结时，以已审核训练记录为依据。

# 12｜本地优先的媒体资产存储与 GitHub 分工

> **D-016 / Q-006 已确认（2026-11-11）**：仓库会 clone 到本地，图片、视频、原图、前后对照与其他较大的训练素材**主要在本地维护，不同步大文件到 GitHub**。GitHub 负责规范、案例元数据、知识卡、训练记录与可公开的文字索引。该方案替代先前建议的“媒体仓库/云端大文件混合存储”，不要求 Git LFS，也不要求接入外部资产服务。

## 1. 目标和边界

- **远程 GitHub（版本化文本）**：`docs/`、`materials/**/*.md` 案例卡、`practices/**/*.md` 训练记录、`knowledge/**/*.md` 知识卡、`README.md`、`.gitignore`。
- **本地素材（不随 git push 同步）**：原图、视频、音频、截帧、标注图、裁切/调色前后对照、AI 生成版本、设计工程文件。
- **第三方原作**：公开仓库只记录来源、作者、许可情况和个人原创分析；是否能在本地保存、使用及再分发应遵循对应权利条件与适用法律。本地保存不意味着可以公开提交。
- **例外**：将来若明确希望把少量有合法再分发权限的轻量示意图发布到 GitHub，可单独讨论；目前默认不上传媒体文件。

## 2. 建议的 clone 后目录

```text
aesthetic_training/
├── README.md
├── .gitignore
├── docs/                      # 课程、决策、规则（同步）
├── materials/
│   ├── classic/               # 作品来源与视觉案例资料卡 .md（同步）
│   └── personal/              # 个人案例卡 .md（同步）
├── practices/
│   ├── daily/                 # 每日文字记录 .md（同步）
│   ├── experiments/           # 实验记录 .md（同步）
│   └── reviews/               # 周复盘 .md（同步）
├── knowledge/                 # 概念卡 .md（同步）
└── local-assets/              # 本地创建；整体 gitignore，不出现在远程仓库
    ├── classic/               # 经典参考素材（有权本地使用时）
    │   └── case-0001/
    │       └── original.jpg
    ├── personal/              # 自己的图片/视频/收藏参考
    └── practices/
        └── W01-D01/
            ├── original.png
            ├── annotated.png
            └── experiment-v1.png
```

`local-assets/` 为**建议统一入口**，clone 后由使用者自行创建。Git 不会自动创建被忽略的目录，也不会同步里面的文件。目录中所列的文件名只是说明结构的示例，不代表已有素材。

## 3. 如何在 GitHub 文档中关联本地文件

案例卡或训练记录建议同时写两种引用：

```yaml
source_url: "https://example.org/official-artwork"
local_media:
  - "local-assets/classic/case-0001/original.jpg"
```

- `source_url`：原作可公开分享的**来源网址**，便于远程查阅和核对作者、版权与作品信息。
- `local_media`：**仓库根目录相对路径**，指向本机素材，便于 clone 后在本地查找。
- 不使用 `C:\Users\...` 等绝对路径，也不要在公开仓库填写隐私目录、设备身份信息或不可公开的素材描述。
- GitHub 网页端无法打开 `local-assets/` 的文件是**预期行为**；不能把它当作已在线同步的文件，也不应在 Markdown 用不存在的远程图片链接制造破图。
- 若文件被移动，修改本地路径引用；案例卡保存作品稳定 ID，不把文件名当作唯一身份。

## 4. Git 防误提交保护

项目根目录已增加 `.gitignore`：

- 整个 `local-assets/` 被忽略。
- 其他目录中的常见图片、视频、音频、设计文件及压缩包格式也默认被忽略，避免不小心把原始媒体加入提交。
- **注意**：`.gitignore` 不会删除或忽略已经被 Git 跟踪的文件，也不能阻止 `git add -f` 强制提交；如以后改变媒体公开策略，应先单独核对仓库状态与版权。
- 若需要检查忽略结果，本地可以使用 `git status --ignored` 或 `git check-ignore -v local-assets/practices/W01-D01/original.png`。

## 5. 备份与多设备

- **GitHub 不是本地媒体备份**：仅 clone/pull 仓库不能恢复 `local-assets/`。
- 如果未来换电脑、重装系统或需要跨设备使用，必须自行备份/迁移本地素材；是否引入 NAS、同步盘、专门资产管理工具等尚未确定，不做默认强制要求。
- 远程文档以案例 ID + 原始来源链接为基础，尽量允许在没有本地媒体文件的电脑上继续阅读理论与文字训练结论。
